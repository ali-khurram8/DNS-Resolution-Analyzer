# AI-use disclosure

Course policy requires us to disclose all use of generative AI. This file lists where an AI tool was used, what for, and how its output was checked.

**Tool:** Claude (Anthropic), used through Claude Code (Opus 5.5 model).

| Final check and build fix (`docker-compose.yml`, `README.md`) | Claude ran the lab, the demo, the unit tests, `verify.py` and one test experiment run to check the project against the proposal. The test run was written to the container's `/tmp`, so nothing in `results/` or `captures/` changed. It then changed `docker-compose.yml` so the image is built once: only `r1` has `build:`, and the other six services reuse `dnslab-node:1.0` with `pull_policy: never`. Before, Compose started four parallel builds of the same image. It updated the README to match (repository layout, Section 3 and a troubleshooting entry for "No such image") and deleted the generated `certs/` folder, which Unbound recreates on start. | *[Team: state that you rebuilt the lab from a clean checkout with the new compose file and reviewed the README changes.]* |
| Web dashboard (`scripts/dashboard.py`, `scripts/dashboard.html`, `--json` option in `experiments/compare.py`) | Claude wrote a browser dashboard for the live demo. It runs the same 7 steps as `scripts/demo.py` through `docker exec` and draws the results: an arrow diagram of each resolver query, Do53/DoT/DoH latency bars, a netem control, and the saved results, plots, screenshots and diagram. It also added a `--json` output option to `compare.py`; the default text output is unchanged. After a design critique, Claude redesigned the page around the lab topology. The redesign adds a persistent topology diagram with a packet replay, a one-step-at-a-time view led by each step's key number, and charts built with the `dataviz` skill: a colour-blind-checked palette, shared scales, hover details, a table view per chart, and four charts from `results/summary.csv`. It also adds keyboard shortcuts and a presenter mode. Claude then ran a WCAG 2.1 AA accessibility audit (the Design plugin's accessibility-review skill) and fixed all 19 issues it found: contrast, focus handling, names and roles for screen readers, a shortcut off-switch, a replay off-switch, tooltip behaviour, target sizes and reflow. Claude tested every step in a browser against the running lab, in light and dark mode, at desktop and phone widths. No real screen reader was used. | *[Team: state that you ran the dashboard yourselves and can explain how it works.]* |
